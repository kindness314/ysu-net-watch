# YSU Net Watch

面向 Windows 的燕山大学 `iYanDa` 校园网络认证守护工具。它可以连接
`iYanDa`、完成校园网或宽带认证、持续检查认证状态，并在确认掉线后自动
重新认证。

> [!IMPORTANT]
> 本项目是非官方工具，与燕山大学、锐捷网络及各宽带运营商无隶属或授权
> 关系。请仅用于本人账号及获准使用的校园网络，不得绕过验证码、设备确认
> 或学校安全策略。门户升级后，部分功能可能暂时失效。

## 功能

- 校园网认证，以及中国联通、中国电信、中国移动宽带认证。
- 无参数启动交互式控制台，支持方向键选择、切换认证模式、下线和停止监听。
- 自动/定时恢复时，Wi-Fi 开启但未连接任何网络会自动连接 `iYanDa`；连接热点
  或其他 Wi-Fi 时跳过。手动选择“切换到 iYanDa”才会主动切换当前网络。
- 最多 10 个可独立开关的定时器，可设置执行时间、星期、认证模式和失败
  补偿时间。
- 程序启动、休眠恢复或调度短暂阻塞后会补执行当天错过的定时任务；若主任务已经
  错过其补偿时间，只执行一次，避免两次认证紧挨着运行。
- 默认定时器 1 在工作日 06:00 启动最近手动选择的账号监听（初始中国联通）；
  本轮持续认证失败时，08:00 使用同一账号再尝试一次。
- 连续 3 次 Ping 失败后，只有 HTTP 探测明确重定向到燕大认证门户，或
  HTTPS 门户连续确认离线，才会读取凭据。
- 疑似掉线后默认等待 120 秒复核，避免瞬时网络波动触发认证。
- 暂时性认证失败连续 5 次后停止监听，并将脱敏原因写入日志；账号密码被明确
  拒绝或账号被冻结、锁定、封禁、停用时第一次响应即停止，绝不自动重试。
- 门户明确返回登录来源 IP 被冻结、封禁、锁定、限制或列入黑名单时，立即停止
  同一 IP 的认证重试，并返回独立退出码 `26`；普通 IP 地址校验失败不会被当作冻结。
- 门户明确报告“认证设备数达到上限”时立即返回专用错误并停止该账号重试，
  不进入当天补偿；可用 `--try-next-account` 按账号表顺序尝试后续同服务账号。
- 宽带账号明确被旧设备占用时，可按门户设备管理流程下线旧会话并补偿登录。
- 使用 Windows 凭据管理器保存账号密码；设置文件只保存非敏感偏好。
- 多账号档案：校园网和不同运营商的账号独立保存，可切换、改名、更新、删除。
- 账号一次性试验证：可在不启动监听、不踢旧设备的前提下确认指定账号的门户状态。
- 默认定时器 1 跟随最近选择的账号及服务；自定义定时器 2～10 固定绑定各自账号。
- 夜间停网保护：周一至周四 23:30 起暂停自动认证，到次日定时器 1 的时间恢复。
- 单文件 Windows EXE，目标电脑无需预装 Python。

## 系统要求

- Windows 10 或 Windows 11。
- 已开启的 Wi-Fi 网卡；程序不能绕过飞行模式、物理无线开关或管理员禁用。
- 可连接到燕山大学 `iYanDa` 无线网络。
- 本人合法的校园网或宽带认证账号。

## 快速开始

### 使用 Windows EXE

当前预发布版本为 `0.3.0rc1`（Git 标签 `v0.3.0-rc.1`）。它保留账号拒绝/冻结后的
单次即停保护，并包含认证设备数上限检测、可选账号顺序回退、一次性账号试验证，以及
来源 IP 冻结分类和终端输出安全加固。7 月旧版有真实认证成功记录，但本预发布版尚未
在解冻账号上完成实网认证，因此不能只凭离线测试宣称认证可用；稳定版 `v0.2.1` 仍可
在 Releases 中回溯。

从本仓库的 Releases 下载 `ysu-net-watch.exe`，核对发布页提供的 SHA-256
后运行。程序没有商业代码签名，Windows SmartScreen 首次运行时可能显示
“未知发布者”。

首次保存凭据：

```powershell
.\ysu-net-watch.exe credential set --mode campus
.\ysu-net-watch.exe credential set --mode broadband
```

随后直接打开：

```powershell
.\ysu-net-watch.exe
```

### 从源码安装

需要 Python 3.10 或更高版本：

```powershell
git clone https://github.com/kindness314/ysu-net-watch.git
cd ysu-net-watch
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
ysu-net-watch
```

## 凭据安全

推荐使用 Windows 凭据管理器。`credential set` 会通过隐藏输入读取密码，
密码不会出现在命令行参数、项目文件或普通设置文件中：

```powershell
ysu-net-watch credential set --mode campus
ysu-net-watch credential set --mode broadband
ysu-net-watch credential delete --mode campus
ysu-net-watch credential delete --mode broadband
```

环境变量仅作为回退方式：

```powershell
$env:YSU_CAMPUS_USERNAME = "学号"
$env:YSU_CAMPUS_PASSWORD = "密码"
ysu-net-watch login --mode campus --credential-source env
```

程序首次读取环境变量后会将其从当前进程环境中移除，但环境变量仍不能对
管理员、同权限调试器或进程转储保密。不要把真实凭据写入 `.env`、源码、
Issue、日志或命令行参数。

## 交互控制台与定时器

不带子命令运行时进入常驻控制台：

```powershell
ysu-net-watch
```

菜单中的“修改常用/定时设置”可以配置常用认证模式和最多 10 个定时器。
“账号管理”现作为主菜单的独立栏目，可直接添加账号；选择带有“修改：”前缀的账号
即可修改别名、凭据、常用状态、监听目标或删除档案。
每个定时器支持：

- 开启或关闭。
- 自定义执行时间。
- 工作日、每天、周末或自定义星期。
- 校园网或指定宽带运营商。
- 可选的失败补偿时间。

设置保存在 `%LOCALAPPDATA%\YSUNetWatch\settings.json`，不包含账号密码。
定时器依赖程序保持运行；窗口可以最小化，但退出程序后定时器不会运行。
同一分钟有多个定时器时，编号较小的优先执行。

程序会补执行当天因启动较晚、休眠或调度暂停而错过的任务。当前分钟的准时任务
优先于补执行任务；同时错过多个任务时，以计划时间较晚者优先，其余任务当日记为
冲突跳过。运行中把一个定时器改到已经过去的时间不会立即认证，而是等下一个有效
日期。Windows 无法确认 Wi-Fi 状态时主任务记为失败，可在配置的补偿时间再试；
明确连接热点或其他 Wi-Fi 时仍只跳过。

任务领取与补偿状态保存在
`%LOCALAPPDATA%\YSUNetWatch\schedule-state.json`。该账本只含任务 SHA-256
指纹和日期，不含账号、密码、Cookie 或认证会话；因此同一天退出或重启程序不会
再次强制认证。任务设置或所绑定凭据版本改变后会产生新指纹。账本损坏时程序会
安全停止定时调度并在界面报告，不会假装从未运行而重复认证。仅在程序完全退出后
才能人工删除该文件；删除会清除当天去重和补偿记录。

失败补偿只支持同一天，并且必须晚于主任务时间；需要跨日行为时应使用另一个
定时器。若高优先级任务因账号缺失或启动前检查失败而未被接受，其余到期任务不会
被提前标记为冲突跳过，会在后续调度周期继续处理。

### 默认定时器跟随最近选择

- 手动确认“切换并监听”、修改常用认证或设置常用账号后，定时器 1 的账号、
  校园网/宽带模式及运营商同步更新。只是移动菜单光标、取消、改名、更新密码、
  停止监听或下线不会更改这个选择；认证失败也不会自动换回旧账号。
- 选择保存在本机设置中，重启程序仍有效。只保存档案 ID，不额外保存账密。
  初次升级没有最近选择记录时，按当前常用模式、运营商及其常用账号初始化，
  修正“常用电信但默认定时器仍为联通”的旧配置。
- 定时器 1 的时间、星期、开关和补偿时间不变；关闭的定时器不会被自动打开。
  定时器 2～10 的固定绑定不变，自动任务也不会覆盖最近的手动选择。
- 修改账号后，旧账号本轮失败和迟到结果失效；新目标从下一次匹配时间参与
  定时调度。不会把旧账号 06:00 的失败借给新账号触发 08:00 补偿。
- 定时器列表标注“跟随最近选择”或“固定账号”。定时器 1 编辑菜单可直接修改
  最近选择；若需要始终固定某个账号，请使用定时器 2～10。
- 命令行 `login` / `watch` 选择已保存档案时同样记住选择；仅使用
  `--credential-source env`、未指定档案的临时认证不改变定时目标。

持续监听校园网：

ysu-net-watch watch --mode campus --credential-source windows
```

ysu-net-watch watch --no-auto-wifi --mode campus
```

```powershell
ysu-net-watch --help
ysu-net-watch watch --help
```

## 掉线判断

正式参数默认每 60 秒检查一次：

1. 对默认目标 baidu.com 连续探测三次，由同一个 Ping 进程完成。
2. 只有全部 Ping 失败，才检查固定 HTTP 探测地址。
3. 探测地址必须返回重定向，且目标主机精确匹配燕大认证门户；攻击者后缀
   域名不会被接受。
4. 公共探测无法确认时，仅在当前确实连接 `iYanDa` 的情况下查询 HTTPS
   门户状态。
5. 默认等待 120 秒再次确认。
6. 确认认证失效后才从凭据管理器读取账号密码并认证。

连接热点、离开 `iYanDa`、门户状态不明确或仅发生普通网络故障时，程序
不会提交凭据。

门户当前在进入 `portal-main` 时会返回一次同域名的 HTTP 地址，再立即以
308 跳回 HTTPS。程序只对精确的 `auth1.ysu.edu.cn/portal/portal-main`
GET 路径在本地直接升级为 HTTPS，不会发出中间的明文 HTTP 请求；任何其他
HTTPS 降级仍按安全异常立即停止。

`getCurrentNode` 只读取门户流程状态，不负责推进流程。程序完成 CAS 和
`serviceSelection` 后读取一次节点；节点字段为空时不会继续提交 `serviceLogin`。
若 `serviceLogin` 返回普通异常或 `workFlowNode is empty`，程序先只读复核
`userOnline`：已经在线则按成功处理；确认离线后仅允许丢弃旧 Cookie、建立一次
全新门户会话重试，第二次仍失败即按协议变化停止。明确的密码拒绝、账号冻结/锁定
或登录来源 IP 冻结/封禁仍在第一次响应后立即停止。

### 认证与网络恢复的区别（2026-09-09 修复版）

- 服务登录成功后，最多查询五次门户在线状态，等待间隔为 2、3、5、5 秒
  （请求耗时另计）。下线切换也会等待门户状态更新。
- 门户确认在线后，最多进行三次外网复核，等待间隔为 3、5 秒。门户仍在线、
  外网未恢复或状态请求超时时，持续监听会显示“网络待恢复”，不按密码错误
  累计到五次退出；外网恢复后自动回到正常监听。超时不清空此前已记录的明确
  认证失败次数，同一轮恢复仍在第五次明确失败时停止。
- 普通的暂时性认证失败最多尝试五次，然后停止该监听并记录最后的阶段、类别和
  原因。门户明确返回密码/账号错误、账号冻结或锁定时只提交一次，返回终止码 `23`；
  明确返回登录来源 IP 冻结/封禁时返回 `26`。两类结果当天都不会在补偿时间再次
  提交相同凭据。
- 每次认证重试重新读取 Windows 凭据；每次重试及监听中的门户请求都会检查
  停止信号和校园 Wi-Fi。离开 iYanDa 后暂停认证，连接热点时不会继续提交。
- 使用环境变量的凭据仍在首次读取后缓存在当前进程；更换这种凭据需要重启。

多账号预览版已包含上述认证修复，并沿用旧版 Windows 凭据和定时设置。

### 重连与定时任务的保护（fix1）

- 每轮恢复最多请求一次旧设备下线。即使该请求超时、结果未知，也不会重新发出；
  只有确认恢复、重新启动监听或夜间保护结束后进入新一轮，才重新允许请求。
- 失败计数跨主循环保留；确认校园网络/门户恢复，或夜间保护结束后开始新一轮。
  热点联网不重置校园网失败计数。
- 菜单“定时调度”单独显示运行健康状态。调度异常后每 15 秒继续检查后续任务；
  Wi-Fi 查询失败可触发已配置的补偿，不会因一次异常永久丢失后续调度。
- 修改定时器绑定、时间、星期、开关、补偿时间或更新其账号凭据，会使旧任务的
  失败记录和迟到结果失效；新配置从下一次匹配时间生效。仅修改别名不影响补偿。
- 多个定时器指向同一账号且复用同一个正在运行的监听时，每个定时器都保留独立
  任务记录；监听若失败，各自主任务仍可按自己的设置进入补偿。
- 日志文件因占用、权限或磁盘异常暂时不可写时，控制台只提示一次，监听不会因此
  崩溃；恢复写入后会自动清除该降级状态。

## 多账号使用

在主菜单选择 **5. 账号管理**：

1. 添加账号：给它取一个别名，选择校园网或运营商，再输入账号和隐藏密码。
2. 选择档案后，可“切换到此账号并监听”“设为该服务常用账号”、改名、
   更新账密、一次性试验证或删除。最多 20 个档案，包括兼容档案。
3. 自定义定时器 2～10 的“绑定账号”固定使用该档案；默认定时器 1 跟随最近选择。
4. 删除被定时器引用的账号时，必须明确停用相关定时器；正在监听的账号
   要先停止或切换。默认不会在认证失败后自动尝试其他账号；需要设备上限回退时
   显式使用下方的 `--try-next-account`。

切换会先停止旧监听，确认目标凭据可读取，再下线旧会话并使用目标账号登录。
下线失败则不继续登录。界面“监听目标”表示选定档案；目前尚未依据现场门户
身份字段独立核验账号，已在认证完成时明确提示，不把任意既有在线会话当作换号成功。

也可使用命令行；`ID` 从 `account list` 获取：

```powershell
.\ysu-net-watch-timer-follow-20260912.exe account list
.\ysu-net-watch-timer-follow-20260912.exe account add --label "我的电信" --mode broadband --service telecom
.\ysu-net-watch-timer-follow-20260912.exe account update --profile ID
.\ysu-net-watch-timer-follow-20260912.exe account default --profile ID
.\ysu-net-watch-timer-follow-20260912.exe watch --profile ID
.\ysu-net-watch.exe account verify --profile ID
```

`account verify` 只执行一轮门户认证探测，不启动监听、不记住最近选择，也不会按账号表
顺序回退或踢下线其他设备。验证成功后门户会保持该账号在线，便于随后手动切换监听；
宽带账号被其他设备占用时只报告占用，不执行旧设备下线。若当前已经存在在线会话，默认
不会读取或提交指定账号凭据，而是返回退出码 `25`；确认要切换当前会话后再使用：

```powershell
.\ysu-net-watch.exe account verify --profile ID --force-switch
```

`--force-switch` 会先复核并下线当前会话，再验证指定账号；它仍不会踢其他设备。密码错误、
冻结/锁定、来源 IP 冻结/封禁、认证设备数上限、网络或门户协议异常分别返回退出码
`23`、`26`、`24`、`21`、`30`，
便于脚本和人工区分账号状态。试验同样受夜间保护限制，保护期间不会读取凭据。

命名档案不回退到环境变量或其他账号。旧的 `credential set --mode broadband`
只更新旧共享宽带凭据；更新独立档案请使用账号管理或 `account update`。
外部登录、下线或账号修改命令不能与已运行的控制台并发操作，请在已有窗口管理。

认证设备数达到门户上限时，默认只停止当前账号，不会盲目重复提交。需要顺序回退时
显式开启开关；它只筛选与当前账号相同模式/运营商的档案，按 `account list` 的档案
顺序从当前档案之后逐个尝试，不循环回到前面的账号：

```powershell
.\ysu-net-watch.exe login --profile ID --try-next-account
.\ysu-net-watch.exe watch --profile ID --try-next-account
.\ysu-net-watch.exe console --try-next-account
```

只有明确的设备数量上限会触发回退；密码错误、账号冻结/锁定、协议变化、网络异常
和普通“账号已在线”恢复失败都会按原有安全策略停止或等待，不会自动换号。候选账号
认证成功后，单次登录会记住该账号；控制台会把当前监听目标更新为实际成功的档案。

### 从旧 fixed 版升级

退出旧程序，启动新版即可。原校园网和宽带凭据会以兼容档案出现：
“旧校园网”“旧宽带·联通/电信/移动”。三个旧宽带档案最初仍引用同一份旧凭据，
首次更新其中一个档案时才将它独立保存，其他档案不受影响。

旧自定义定时器按原服务绑定兼容档案；定时器 1 以当前常用账号初始化跟随目标。
首次从旧 fixed 版保存新版设置时，原设置备份为
`%LOCALAPPDATA%\YSUNetWatch\settings.legacy-v1.json`；不自动删除旧凭据。
从此前多账号预览版首次保存时，备份为同目录的 `settings.pre-timer-follow.json`。
新档案按 UUID 和凭据版本分开保存，更新保存失败时保留原引用；若系统在写入中
异常终止，可能留下未引用的加密凭据项，但不会把它自动用于其他账号。

## 夜间停网保护

默认开启，校园网和所有宽带账号均适用：

| 时段 | 行为 |
| --- | --- |
| 周一、二、三、四的 23:30 起 | 暂停自动认证和踢设备，不读取认证凭据、不累计认证失败 |
| 次日定时器 1 的执行时间，默认 06:00 | 已运行的监听自动恢复；正常的定时器也可在此时启动绑定账号 |
| 周五恢复后至周一 23:30 | 不进入夜间暂停，正常监听 |

保护区间包含开始时间，不包含结束时间。例如周四 23:30 至周五 06:00 会暂停，
周五 23:30、周六凌晨不会暂停。中途的认证请求跨过 23:30 才返回失败时，
也不会因此累计到退出码 20。已经发出的请求无法撤回，但不会继续后续认证/踢设备步骤。

在 **常用/定时设置** 中，选择“夜间保护：开/关”即可直接切换；默认开启。
选择“修改夜间保护恢复时间”可以单独修改恢复时间。
恢复时间跟随定时器 1 的时间，独立于该定时器开关；关闭定时器 1 不会让已有
监听整天暂停。若程序没有运行或已手动停止监听，结束保护时不会凭空启动一个监听。
程序需保持运行，不能自行唤醒关机或休眠的电脑；Wi-Fi 也仍需开启。

恢复时未连接任何 Wi-Fi 会尝试连接 iYanDa，连接热点则跳过。临时连接失败
会继续等待重试。正常时段明确认证失败五次仍停止监听，定时任务的失败补偿仍有效。

## 日志与隐私

日志默认写入 `%LOCALAPPDATA%\YSUNetWatch\logs\ysu-net-watch.log`，并在达到大小限制后轮换。
也可以使用 `watch --log-file` 指定其他位置。
日志会过滤：

- 密码及完整用户名。
- Cookie、Token、ticket、sessionId 和 Authorization。
- 完整 IP、MAC 和请求正文。

提交 Issue 前仍请人工检查日志，并删除任何不希望公开的信息。

## 退出码

| 退出码 | 含义 |
| ---: | --- |
| `0` | 正常结束或认证成功 |
| `5` | 另一个控制台/认证操作正在运行 |
| `10` | 缺少凭据或账号设置无效 |
| `20` | 监听连续认证失败；单次 login/logout 为认证或下线失败 |
| `21` | 单次操作或 watch --once 的认证阶段网络暂未确认；持续监听遇到此状态会继续运行 |
| `22` | 单次操作或 watch --once 处于计划停网时段；持续监听会保留并等待恢复 |
| `23` | 门户明确拒绝账号/密码，或账号已冻结、锁定；已停止自动重试和当日补偿 |
| `24` | 门户明确报告账号认证设备数达到上限；已停止该账号重试和当日补偿 |
| `25` | 当前已有在线会话，试验证未提交指定账号凭据 |
| `26` | 门户明确报告登录来源 IP 被冻结、封禁或限制；已停止该 IP 重试和当日补偿 |
| `30` | 认证门户协议发生变化 |
| `40` | 无法配置或连接指定 Wi-Fi |
